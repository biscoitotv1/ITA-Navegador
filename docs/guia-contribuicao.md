# Guia de Contribuição

## Visão geral

Este guia define as práticas mínimas para manter o repositório organizado e compreensível durante a fase inicial de desenvolvimento.

## Fluxo recomendado

1. Crie uma branch específica para a tarefa.
2. Mantenha a branch focada em uma alteração por vez.
3. Atualize a documentação sempre que houver mudança relevante em comportamento, estrutura ou processo.
4. Revise a alteração antes de concluir a tarefa.
5. Garanta que a documentação e o código permaneçam consistentes.

## Boas práticas

- Use nomes claros para branches e commits.
- Prefira mudanças pequenas e bem delimitadas.
- Documente decisões importantes e descrever problemas/opções quando a implementação exigir.
- Mantenha o README principal e a pasta `docs/` atualizados conforme o projeto cresce.

## Quando atualizar a documentação

A documentação deve ser revisada quando houver:

- criação de novas funcionalidades;
- alterações na arquitetura;
- mudanças no fluxo de desenvolvimento;
- inclusão de ferramentas ou dependências;
- mudanças no processo de revisão ou validação.

## Regras iniciais

- O repositório precisa permanecer legível para novos participantes.
- A documentação deve descrever o estado real do projeto e não apenas o desejado.
- Qualquer expansão da estrutura deve ser refletida no README e nos documentos de apoio.
